# 维护指南

这份文档写给**不需要懂前端**的维护者。发布一场活动只做两件事：复制模板、填 markdown。

## 一、发布一场新活动

把 `docs/模板/活动目录名/` 整个复制到 `src/activity/new/` 下，改成你自己的目录名，然后填内容、提交。

```
src/activity/new/2026-10-kotlin-share/
  card.md      必需
  detail.md    可选
  signup.md    可选
  back.md      可选
  assets/      可选
```

**目录名随便起**，页面不看它。推荐写成 `年-月-活动短名`，纯粹为了将来在文件夹里一眼找到。

## 二、`card.md` 怎么填

开头那段被 `---` 夹住的叫 frontmatter，逐行对应下表。

|     字段     |    必填    |               怎么填                |
|:----------:|:--------:|:-------------------------------:|
|  `title`   |    是    |             活动名称             |
|  `during`  |    是    | 活动时间跨度 `["开始", "结束"]`，照 `2026-10-18T19:00:00+08:00` 的样子改 |
|  `enroll`  |    否    |       报名时间跨度，写法同上       |
|  `weight`  |    否    |   排序权重，不填按 50 算，越大越靠前   |
|    `sp`    |    否    |       置顶，见第五节，默认不置顶       |
|  `venue`   |    否    |      线下地点，没有就删掉这一行      |
|  `online`  |    否    | 线上渠道，每行 `- ["显示的文字", "链接"]` |
|  `action`  |    否    | 按钮，写成 `[按钮文字](链接)`；不填则显示「点我报名!」且点了不跳转 |

**活动处在哪个阶段由这两个时间跨度自己算出来，不用你手写状态**：

|            什么时候            |   页面显示   |      时间轴上的圆点      |
|:---------------------------:|:--------:|:----------------:|
|     还在 `enroll` 区间内     |  报名中   |   向内聚集的涟漪   |
| 报名已截止、活动还没开场 |  进行中   | 纯圆环，没有涟漪 |
|     在 `during` 区间内      |  进行中   |   向外发散的涟漪   |
|     过了 `during` 的结束     |  已结束   |  灰色半透明，没有涟漪  |

**活动延期或改时间，只改 `during` 就行**，别的都不用动。

## 三、几个 markdown 各管什么

|     文件      |            显示在哪            |
|:-----------:|:---------------------------:|
|  `card.md`  |   卡片正面：标题、地点、日期、按钮   |
| `detail.md` |        卡片中间那块正文        |
| `recap.md`  | 活动结束后的回顾，会顶替 `detail.md` |
| `signup.md` |      报名须知，压在正文底部      |
|  `back.md`  |  明信片背面，右键翻过去才看得到  |

**不需要的文件直接删掉**，页面不会留下空位。想放照片、PPT、视频就放进 `assets/`，在 markdown 里写 `![说明](./assets/文件名)` 即可。回顾里想嵌哔哩哔哩或会议录像，直接写 `<iframe src="..."></iframe>`，宽度自动适配。

`back.md` 一般就一两行题词或落款，也可以放一排协作方的 logo，整块内容会在背面水平垂直居中。不写这个文件，背面就是一片炫彩。

## 四、活动结束了怎么办

页面会自己认出来，你不用改任何字段。为了将来好找，**把整个目录从 `src/activity/new/` 移到 `src/activity/history/`** 即可，纯属归档整理，不影响显示。

## 五、想让某场活动排前面

`weight` 调大即可，默认 50。同一批活动里数字大的排前面。

`sp: true` 是更强的一档：它让这场活动**跳出自己的分类**去比较。已结束的活动本来只会出现在历史栏，挂上 `sp: true` 就能回到最新活动栏——公示获奖名单一类的内容用得上。

注意 `sp` 只是换一种比较口径，**不保证排到第一**：它会从头逐个比权重，停在第一个比自己小的前面。

## 六、页面出错了怎么查

提交后 CI 会检查 `card.md` 的必填项、日期能不能解析、markdown 里引用的图片是否真的存在。红了就看报错那一行，多半是日期写错格式或者图片名字对不上。本地想先自查，跑 `node scripts/check-content.mjs`。
